# Участие в разработке

Спасибо за интерес к Dream&Go. Проект развивается по фиксированному ТЗ V1.0: сначала завершаем обещанные пользовательские сценарии, затем рассматриваем новые идеи для следующей версии.

## Перед началом

1. Прочитайте [единое ТЗ](docs/PRODUCT_SPEC.md).
2. Проверьте [дорожную карту](docs/ROADMAP.md) и [план завершения](docs/DELIVERY_PLAN.md).
3. Для изменений Firebase ознакомьтесь с [матрицей доступа](docs/FIRESTORE_ACCESS_MATRIX.md).
4. Работайте в отдельной ветке. Не отправляйте экспериментальные изменения прямо в `main`.

## Принципы изменений

- Один PR — одна логическая задача.
- Сохраняйте совместимость с существующими пользовательскими данными.
- Не меняйте Firestore Rules на более разрешительные без соответствующих Emulator tests.
- Не переносите секреты, реальные email, токены и пользовательские данные в репозиторий.
- Не добавляйте зависимости, если задачу можно решить существующими средствами.
- Не оставляйте отладочные логи, мёртвый код и комментарии, которые больше не соответствуют реализации.
- Не удаляйте комментарии, объясняющие ограничения безопасности, инварианты и причины нетривиального решения.
- Новые функции вне MUST-объёма V1.0 фиксируйте отдельно для следующего релиза.

## Проверки перед PR

Требуется Node.js 22+.

```bash
npm install --prefix server --no-package-lock --ignore-scripts
npm test
npm run check
npx --yes firebase-tools@14.22.0 emulators:exec --only auth,firestore --project demo-dream-and-go "npm --prefix server run test:emulator"
```

Если менялся только UI, дополнительно проверьте основные сценарии в браузере и адаптивность. Если менялись права доступа, добавьте позитивные и негативные Rules Emulator tests для владельца, другого пользователя и неавторизованного клиента.

## Документация

Вместе с кодом обновляйте `docs/ROADMAP.md` — DONE / NOT DONE с доказательствами, `docs/INTEGRATION_PLAN.md` при изменении интеграции и профильный документ архитектуры/безопасности при изменении контракта.

## Готовность задачи

- Код соответствует ТЗ и не расширяет scope самовольно.
- Проверки пройдены на актуальном коммите.
- Ошибки и неопределённые сетевые исходы обработаны.
- Нет секретов и ненужных файлов.
- Документация соответствует фактическому состоянию.
- Production Firebase и пользовательские данные не затронуты без отдельного согласования.
