# Политика безопасности

Безопасность аккаунтов и пользовательских данных — обязательное условие Dream&Go.

## Сообщение об уязвимости

Не публикуйте сведения об эксплуатируемой уязвимости, приватные данные, токены или рабочие сценарии атаки в открытых Issues.

Используйте приватную функцию **Report a vulnerability** на вкладке Security репозитория, если она доступна. Если она отключена, свяжитесь с владельцем репозитория приватно через GitHub и приложите минимальное воспроизводимое описание.

Не включайте в отчёт реальные пароли, действующие токены, персональные данные других пользователей или дампы production.

## Правила для разработчиков

- Не коммитьте `.env`, service-account JSON, приватные ключи, токены и пароли.
- Используйте демонстрационный Firebase project ID для Emulator tests.
- Не ослабляйте Firestore Rules без path-specific тестов и review.
- Не доверяйте UID, email, sender ID, owner ID и ролям, переданным клиентом как обычные поля.
- Серверные операции обязаны самостоятельно проверять аутентификацию, принадлежность данных и входные значения.
- Любая миграция требует backup, dry-run, отчёта конфликтов и rollback-плана.
- Production deployment выполняется только после staging-приёмки и отдельного подтверждения владельца.

## Текущая оговорка

Интеграционная ветка содержит кандидатные серверные функции и deny-by-default Firestore Rules. Наличие этих файлов в Git не означает, что они развёрнуты или проверены в production.
